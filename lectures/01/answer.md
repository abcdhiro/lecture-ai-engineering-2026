# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
  素のLLMに「AIE2026の宿題の『3レベル』とは?」と聞いたところ、講座の実物を知らないため、「レベル1=基礎(ツール活用)、レベル2=応用(API/RAG)、レベル3=発展(自社トレーニング)」といった一般的なスキル習熟度の分類を複数パターン、確信を持って推測で答えた。

- 用語集の正しい意味と比べて気づいたこと：
  実際の3レベルは「基礎・実装・発展」という宿題の難易度区分であり、モデルの回答とは異なっていた。モデルは知らないことでも「分からない」とは言わず、もっともらしい一般論で埋めてくる(ハルシネーション)。一方でLoRAのような一般的な用語は概ね正しく答えた。

- 表示できたトークン数（入力 / 出力）：
  会話形式で3問続けて質問したところ、入力トークンが 13 → 61 → 343 と増加した（出力は 38 / 272 / 323）。LLM自体は過去の会話を記憶しておらず、履歴を保持する＝これまでのやりとり（過去の質問と回答）を毎回まとめてモデルに送り直しているため、会話が進むほど入力トークンが増える。特に2問目の長い回答（大学3校の説明）が3問目の入力に丸ごと含まれ、343まで跳ねた。便利さとコスト（トークン＝課金・レイテンシ）のトレードオフを定量的に確認できた。

## 宿題

- 取り組んだレベル：実装
- やったこと：
  `app/ask.py` を改修し、会話履歴を保ったまま続けて質問できるようにした。
  - 元は `generate_content(contents=question)` の「1問1答」で履歴を持たなかった。
  - `client.chats.create(model=MODEL)` で会話(chat)を作り、`chat.send_message(question)` で送る形に変更。chat が履歴を内部に保持する。
  - `ask()` は残しつつ、引数を `ask(question)` から `ask(chat, question)` に変更。
  - `main()` を `while True` のループにし、`input()` で繰り返し質問を受け付け、`exit`/空入力で終了するようにした。
  - 会話中にAPIエラーが起きても終了せず `continue` で次の質問に進むようにした。
  - あわせて `response.usage_metadata` から入力/出力トークン数を表示するようにした（演習のTODO対応）。

- 結果：
  以下のやりとりで履歴が効くことを確認した。
  - 「カリフォルニア州で一番人口が多い都市は?」→ ロサンゼルス
  - 「そこの有名な大学を3つ教えて」→ UCLA / USC / Caltech（「そこ」=LAと理解）
  - 「その中で一番学生数が多いのは?」→ 挙げた3校を比較して回答（「その中で」=3校と理解）
  代名詞で主語を省いても前の回答を踏まえて答えており、履歴が保持できている。改修前の1問1答では成立しない質問である。


- 気づき・疑問：
  (1) chat は **ループの外で1回だけ** 作る必要がある。ループの中で作ると毎回空の会話が作り直され、履歴が消えて1問1答に戻ってしまう。履歴を「同じ箱に積み上げる」構造を意識する必要があった。
  (2) 3問目でモデルがUCLAとUSCの学生数を答えた際、「断トツでUCLA」と断言しながら直後に提示した数字ではUSCの方が多く、結論と根拠が矛盾していた。一般知識(州の最大都市など)では誤らなかったのに、固有名詞の細かい統計では確信と事実がズレる。UCLAのAIの授業で学んだ "Jagged Frontier"(得意・不得意の境界は事前に分からず、実験して確かめるしかない)を実感する例だった。
  (3) UCLAのAI関連授業で学んだ「タスクを解くには問題仕様・文脈・ソルバーの3点が要る」という枠組みに照らすと、今回は素のLLM(ソルバー)に会話履歴という文脈を与える作業にあたる。文脈がないと代名詞を含む質問が破綻し、履歴を渡すと成立する。文脈エンジニアリングの重要性を最小構成で確認できた。次回以降、用語集を検索する RAG 構成へ発展させると、この「固有の文脈が足りない」問題がどう改善するかを確認したい。
